## 📖 项目简介

**SMSClient** 是一款采用 **Tauri 2 + Rust + React 19** 构建的高性能轻量级 Windows 桌面应用。
它直接调用 Windows 系统的原生 WinRT 移动宽带接口（`Windows.Devices.Sms.SmsDevice2`），无需安装额外的 AT 串口调试工具，即可在带有 SIM 卡槽的笔记本（如 ThinkPad、Surface Pro LTE/5G 等）上原生收发短信、管理会话、联系人群发，并支持实时桌面通知。

- **超轻量体积**：单文件绿色版大小仅约 4.2 MB，内存占用低（~30MB）。
- **零额外驱动**：利用 Windows 10/11 内置 WWAN 移动宽带服务，即开即用。
- **免安装便携**：支持便携模式，本地 SQLite 数据库独立存储。

## ✨ 主要功能

1. **设备与 SIM 状态感知**：
   - 自动检测并枚举 Windows 蜂窝调制解调器（SmsDevice2）；
   - 实时显示运营商名称（中国移动/中国联通/中国电信等）、网络制式（4G/LTE）及信号强度 dBm。

2. **会话式短信收件箱**：
   - 按联系人/号码智能聚合会话列表，高亮未读状态；
   - 支持运营商长短信（Concatenated SMS）自动分片合并与正序排列显示；
   - 本地全文搜索（按发件人姓名、号码或短信正文）。

3. **短信即时发送与重试**：
   - 支持单发、快捷回复、号码格式自动归一化校验（+86 智能去除与格式化）；
   - 实时计算短信字符数与拆分条数；
   - 失败重发与发送状态跟踪。

4. **高级群发与限速机制**：
   - 支持批量导入号码，支持限速延迟发送（防运营商风控）；
   - 发送进度动态展示，实时统计成功与失败条数。

5. **联系人管理**：
   - 本地联系人名册，与短信收发实时关联并支持写信时快速选择。

6. **Windows 11 原生通知**：
   - 新短信到来时自动触发 Windows 系统原生 Toast 通知。

## 💻 系统与硬件要求

### 1. 硬件支持
- 内置 4G/LTE 或 5G 移动宽带模块并配备有效实体 SIM 卡 / eSIM 的笔记本或平板电脑：
  - **联想 ThinkPad**（如 T14 / X1 Carbon / P14s 等搭载 Quectel EM05-CN / Fibocom 等模块）；
  - **微软 Surface Pro**（LTE / 5G 版）；
  - **戴尔 Latitude**、**惠普 EliteBook** 等商用 WWAN 笔记本。

### 2. 操作系统要求
- **Windows 11 / Windows 10 (64-bit)**
- 必须开启系统短信访问权限：
  > 打开 **Windows「设置」** -> **「隐私和安全性」** -> **「消息 (Messaging)」** -> 开启 **“允许应用访问你的消息”**。

## 🚀 快速开始

### 方式一：下载免安装绿色版（推荐）
1. 从 [Releases 页面](https://github.com/h382110229/smsclient/releases) 下载最新的 `SMSClient-v1.0.0-Windows-x64.zip`；
2. 解压到任意目录，直接双击运行 `smsclient.exe`；
3. **便携存储提示**：若希望短信数据保存在 U 盘或程序自身目录下，只需在 `smsclient.exe` 同级目录下新建一个名为 `data` 的文件夹即可。

### 方式二：从源码编译构建

#### 环境准备
- Node.js >= 18
- Rust 工具链（`rustup default stable-x86_64-pc-windows-msvc`）
- Visual Studio C++ 生成工具

#### 构建步骤
```bash
# 1. 克隆代码库
git clone git@github.com:h382110229/smsclient.git
cd smsclient

# 2. 安装前端依赖
npm install

# 3. 本地开发调试模式
npm run tauri dev

# 4. 编译独立绿色发布包 (内嵌前端静态资源，单 exe)
npm run tauri build -- --no-bundle
```
编译产物位于：`src-tauri/target/release/smsclient.exe`。

## 🛠️ 常见问题与排障

### Q1: 提示“未检测到 4G/LTE 蜂窝设备 (SmsDevice2)，已回退 Mock 通道”？
- **原因 1：Windows 消息隐私权限未开启**：
  请前往系统「设置」->「隐私和安全性」->「消息」，开启允许应用访问短信。
- **原因 2：SIM 卡未就绪或手机网络已关闭**：
  检查 Windows 任务栏右下角网络连接中，“手机网络 (Cellular)” 是否已开启并成功识别到运营商。
- **原因 3：ThinkPad / 笔记本盒盖休眠导致 WWAN 模块 USB 掉电（Code 45）**：
  若笔记本在休眠唤醒后突然无法识别网卡，这是 Windows Modern Standby 机制将内部 M.2 插槽置于 D3cold 睡眠。由于 Windows 默认启用了“快速启动”（Hiberboot），普通关机无法彻底为硬件断电复位。**请直接点击开始菜单的【重启】计算机**，主板 BIOS 即可完全重新初始化并上电枚举 4G 模块。

### Q2: 为什么连续收到几条短信后，后续突然收不到了？
- **v0.2.0 已彻底解决**：SIM 卡内部存储容量极小（通常仅 20~50 条容量），满额后运营商会停止向终端下发短信。SMSClient 从 v0.2.0 起引入了“入库即排空”机制，短信存入本地数据库后立即释放 SIM 卡空间，确保持续稳定接收。

## 📝 更新日志

### [v1.0.0] - 2026-11-09
- **[版本号全局统一]** 统一全应用版本标识为 v1.0.0（前端侧边栏、仪表盘、设置页面及 Tauri/Cargo 基础配置全面对齐）；
- **[长短信气泡智能拼合]** 前端全面引入长短信分片拼合算法（`mergeLongMessages`），将跨运营商切片的验证码及通知自动合并为单个完整气泡展示，告别多行断句阅读困扰；
- **[会话精准置顶]** 修复长短信合并后会话列表排序时序计算，最新收到的长短信即刻在收件箱置顶并联动滚动条；
- **[双模收信实时自愈引擎]** 融合 WinRT 短信事件即时响应与 8 秒心跳轮询双模机制，确保任何网络和系统环境下后续短信均能 100% 毫秒级入库与即时提醒。

### [v0.3.0] - 2026-11-09
- **[架构级根因重构]** 解决主线程 COM STA 死锁、同步 Command 阻塞与全局 DB 锁慢速 I/O 三者叠加导致的白屏“未响应”问题，启动耗时由 10~30 秒降至 0.1 秒极速启动；
- **[MTA 常驻与超时隔离]** 引入基于 `RoInitialize(RO_INIT_MULTITHREADED)` 的常驻工作线程与硬超时执行器，确保底层 WWAN 驱动假死时不挂起 UI；
- **[分级超时策略]** 实施设备缓存命中热态 2.5s、未命中冷态宽限 6s、发信 15s 的分级超时调度；
- **[Singleflight 并发互斥]** 增加 `PROBE_LOCK` 并发探测互斥锁，彻底杜绝开机多 Command 并发总线风暴；
- **[2 分钟时间窗精准去重]** 去重升级为 SQLite `datetime(timestamp) >= datetime('now', '-2 minutes')` 滑动窗口，消除双通道重复入库并彻底杜绝相同验证码误杀；
- **[长短信与全卡槽清理]** 完整提取长短信分片，全量清理包括 `SmsStatusMessage` 送达回执在内的所有卡槽，防止 SIM 容量满额断收；
- **[休眠自愈重连]** 后台心跳增加时钟跳变检测（`elapsed > 25s`），自动识别 Modern Standby 盒盖睡眠唤醒并自愈重连；
- **[便携模式路径统一]** 统一便携模式下的 `resolve_db_path`，修复群发任务数据库路径不一致问题。

### [v0.2.0] - 2026-11-09
- **[设备兼容性增强]** 重构 WinRT 蜂窝设备智能枚举器，支持任意带有有效 SIM 槽位的 Windows 笔记本/平板独立使用；
- **[时区显示修复]** 解决接收短信时间戳偏差 8 小时问题，严格遵循 ISO-8601 UTC 解析并按系统当前本地时区格式化；
- **[长短信拼合]** 运营商长短信分片序号解析与按序重组，解决短信乱序及阅读截断拼凑问题；
- **[SIM 存储防爆满]** 引入短信入库后自动清理 SIM 设备端存储机制，根治连续收信后阻塞无法接收后续短信的问题；
- **[事件常驻与心跳守护]** WinRT 事件监听器内存常驻防被 GC，并增设后台定期心跳同步守护；
- **[单文件绿色化]** 优化 Tauri 生产模式内嵌静态资源，无需安装即解压即用。

### [v0.1.0] - 2026-09-24
