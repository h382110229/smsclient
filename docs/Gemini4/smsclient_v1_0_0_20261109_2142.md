## 一、源码深度审计：导致用户“看不见/没提示”的 4 个隐藏代码级 Bug

在审阅你們的交互提案前，我先通读了 `SMSClient_v1.0.0_Source_for_Gemini4_Review.zip` 中的最新实现，发现除了交互层面的“注意力锚定”外，当前代码里有 **4 个逻辑漏洞正在直接吞掉通知事件或破坏消息展示**：

### 1. 致命 Bug 1：`lib.rs:120-124` 心跳线程每 15 秒无条件虚假发射 `sms-received` 事件！
- **源码位置**：`src-tauri/src/lib.rs:120-124`
  ```rust
  if let Ok(msgs) = sms::sync_inbox_non_blocking(&db) {
      if !msgs.is_empty() {
          let _ = bg_app.emit("sms-received", ());
      }
  }
  ```
- **问题机制**：`sync_inbox_non_blocking(&db)` 的返回值是 `crate::messages::list(conn, Some("in"), 200)`——即**数据库里历史收件箱的前 200 条短信**！只要用户的收件箱里哪怕有 1 条去年收到的旧短信，`!msgs.is_empty()` 就永远为 `true`！
- **灾难性后果**：后台线程每 15 秒就会向前端发射一次空的 `"sms-received"` 事件（Payload 为 `null`）。如果你们接下来挂载“监听到 `sms-received` 就弹出顶部横幅 Banner 或播放提示音”，用户的屏幕将**每 15 秒无故弹出一次旧短信横幅**！
- **修复方案**：`sync_inbox_non_blocking` 应当返回 `(Vec<SmsMessage>, Vec<SmsMessage>)` 或仅在新入库了短信（`newly_inserted` 非空）时，才遍历 `newly_inserted` 发射带完整 `{ id, phone, content, timestamp }` 载荷的 `"sms-received"` 事件，**绝不能拿全量历史列表判空**！

### 2. 致命 Bug 2：`utils.ts:147` 长短信合并算法把“3 秒内的两条独立短信”强行粘成一条！
- **源码位置**：`src/lib/utils.ts:142-149`
  ```typescript
  const isSameGroup =
    msg.direction === prev.direction &&
    msg.phone === prev.phone &&
    ((msg.groupId && prev.groupId && msg.groupId === prev.groupId && timeDiff <= 120000) ||
      (msg.partTotal > 1 && prev.partTotal === msg.partTotal && timeDiff <= 60000) ||
      (timeDiff <= 3000) || // <--- 罪魁祸首！
      (timeDiff <= 10000 && (msg.partIndex > 1 || msg.isLong || prev.isLong)));
  ```
- **问题机制**：条件 3 写了 `(timeDiff <= 3000)`，且**没有要求 `isLong` 或 `partTotal > 1`**！
- **灾难性后果**：当中国移动同一服务号在 3 秒内连续下发两条独立短消息（例如第 1 条：“尊敬的客户，您正在办理流量包业务”，第 2 条：“【中国移动】您的验证码是 636642”），前端 `mergeLongMessages` 会直接把第 2 条验证码拼到第 1 条气泡的尾巴上，不会产生新气泡，且会话列表摘要因为只截取前 40 个字符（`truncate(conv.lastMessage.content, 40)`），**左侧会话列表连验证码数字都显示不出来（被第一条短信的前半截挡住了）**！这就是用户觉得“没收到新短信”的重大帮凶。
- **修复方案**：立即删除 `(timeDiff <= 3000)` 这一无条件合并分支！只有当 `msg.isLong || prev.isLong || msg.partTotal > 1 || prev.partTotal > 1` 时才允许合并分片。

### 3. 致命 Bug 3：`Inbox.tsx:187-191` 自动已读 Effect 引发“红点秒闪灭”与循环请求风暴
- **源码位置**：`src/pages/Inbox.tsx:187-191`
  ```typescript
  useEffect(() => {
    if (selectedPhone) {
      markConversationRead(selectedPhone);
    }
  }, [selectedPhone, messages, markConversationRead]);
  ```
- **问题机制**：当用户选中某个会话（甚至程序窗口正最小化在后台，或用户眼睛看着别处），只要该号码来了一条新短信，`messages` 状态一更新，这个 `useEffect` 就在 **1 毫秒内**把新短信改为 `status: "read"`，不仅左侧未读红点瞬间消失（0 秒留存），还会触发 `setMessages` 二次重渲染。更糟的是，`markConversationRead`（`Inbox.tsx:150`）遍历的是原始 `messages` 发送 N 次串行 `await invoke("mark_message_read")`，长短信 3 个分片就会触发 3 次 IPC。
- **修复方案**：
  1. 仅当 **`document.hasFocus()` 为 `true`** 且用户当前正打开该会话时，延迟 **1500ms**（让用户肉眼先看到 `NEW` 徽标和呼吸动效）再标记为已读；若窗口失焦在后台，保留未读红点直到窗口重新获得焦点。
  2. 将 `mark_message_read` 改为按号码批量更新（或在后端提供 `mark_conversation_read(phone)` 单次 SQL：`UPDATE messages SET status='read' WHERE direction='in' AND phone=?1 AND status!='read'`）。

### 4. 隐患 Bug 4：`winrt.rs:68-138` 单一常驻 `winrt-mta-worker` 线程的队列饥饿风险
- **源码位置**：`src-tauri/src/sms/winrt.rs:70-138`
- **问题机制**：你们在 `v1.0.0` 中把 `run_winrt_with_timeout` 改成了派发给全局唯一的 `winrt-mta-worker` 线程串行执行（`while let Ok(task) = rx.recv() { task(); }`）。
- **风险推演**：如果用户点击“发送短信”（`send_sms` 耗时 8~12 秒等待基站 ACK），此时 `winrt-mta-worker` 线程正在阻塞执行 `SendMessageAndGetResultAsync().get()`。在它阻塞的这 10 秒内，前端或心跳发起的 `get_sim_info`、`get_signal_strength`、`status`（超时仅 2.5 秒）被塞进同一个 `rx` 队列排队，结果在队列里干等 2.5 秒后直接触发 `RecvTimeoutError::Timeout`！一旦触发 Timeout，第 125 行调用了 `restart_worker()` 和 `invalidate_device_cache()`，直接把正在发短信的设备缓存给清空了！
- **修复方案**：恢复为每次 `run_winrt_with_timeout` 独立 `std::thread::spawn`（线程内执行 `RoInitialize(RO_INIT_MULTITHREADED)` 耗时仅 2 微秒，且 हमने 已经有 `PROBE_LOCK` 保护设备初始化），或者将 **“慢速写操作（发信/删卡）”与“快速状态读操作”分离到不同的通道**，绝不能让排队等待时间计入硬件超时并误杀正在工作的 Worker。

## 二、四大核心议题裁定（Architectural Rulings）

### 议题 1：会话聚合维度裁决 —— **裁定采用【方案 A 增强版：物理号码独立会话 + 机构语义主标题 + 跨号同机构视觉徽章】**
- **严禁采用方案 B（按机构签名跨号码硬合并会话）**，原因如下：
  1. **回复路由断裂（Reply Routing Ambiguity）**：许多运营商长号码需要用户直接回复指令（如向 `106589666300` 回复 `Y` 确认办理流量包，向 `106589665200` 回复 `TD` 退订）。如果把 `10086`、`106589665200`、`106589666300` 全部合并成同一个“中国移动”会话，当用户在输入框点击回复时，系统根本不知道该把短信发给哪一个物理号码，发错号码会导致业务办理失败。
  2. **伪基站与钓鱼防伪（Anti-Spoofing Security）**：短信正文里的 `【中国移动】` 只是纯文本，任何个人手机号或境外诈骗号（如 `+00852...`）都可以发送一条以 `【中国移动】` 开头的钓鱼短信。如果按签名合并，钓鱼短信会直接混入官方 `10086` 会话流中，造成严重的安全欺诈隐患。
- **最佳实践（方案 A 增强版）**：
  - **聚合主键**：依然严格以规范化后的物理号码 `phone` 作为唯一会话 ID。
  - **双层标题渲染**：
    - 通过正则提取短信正文头部或尾部的 `【([^】]{2,16})】` 作为 `senderOrg`，并结合内置常见短号字典（`10086` $\rightarrow$ `中国移动`，`10010` $\rightarrow$ `中国联通`，`10000` $\rightarrow$ `中国电信`）。
    - **可信前缀校验**：仅当号码属于 `106...` 行业网关号、`100xx` 运营商短号、`95xxx` 银行/金融短号或通讯录已知联系人时，主标题展示加粗的 **`中国移动线上营业厅`**（带绿色认证盾牌图标），副标题以 `11px` 等宽字体展示 `106589665200`；若普通 11 位私人手机号或境外号码正文带有 `【xxx】`，主标题仍显示手机号，仅将签名作为标签提示，防止伪冒。
  - **列表验证码摘要前置**：在左侧会话列表的 40 字预览中，若检测到最新消息含验证码，优先在预览行高亮渲染 `[验证码: 636642]`，不被冗长的敬语遮挡。

### 议题 2：验证码“自动切焦（Auto Focus）”的交互边界 —— **裁定采用【智能无感切焦（Smart Non-Intrusive Auto-Switch）】**
无条件强制切焦会打断正在打字的用户，因此必须设定严格的**三不切（Do-Not-Disturb Guards）**状态机边界：
1. **自动切焦触发条件（必须同时满足）**：
   - 设置项 `auto_focus_otp` 为开启状态（默认 `true`）；
   - 新收到的短信被判定为验证码短信（包含 `验证码|校验码|动态码|确认码|verification|code` 且提取出 4~8 位数字/字母码）；
   - **守护条件 1（路由检查）**：用户当前停留在 `/inbox`（收件箱）或 `/`（首页仪表盘）——若在 `/compose`（写短信）、`/broadcast`（群发）、`/contacts`（编辑联系人）则**绝不自动跳转路由**，仅弹出顶部全局 Banner；
   - **守护条件 2（焦点检查）**：当前 `document.activeElement` **不是** `<input>` 或 `<textarea>`（或者虽然聚焦在搜索框但搜索框内容为空）；
   - **守护条件 3（阅读保护）**：用户在最近 5 秒内没有在右侧消息流中进行鼠标滚轮向上翻阅历史记录的操作。
2. **切焦后的视觉联动**：
   - 自动将 `selectedPhone` 切换为该验证码发件号码；
   - 右侧最新一条验证码气泡框执行 **2 次柔和脉冲高亮（Brand Accent Ring Pulse）**，并在气泡右下角直接内嵌一个 **`[复制验证码 636642]`** 胶囊按钮，用户无需选中文本即可一键点击复制。

### 议题 3：In-App Banner 与 Win11 Toast 的双模退火与防刷屏机制
针对长短信分片（2~3 个分片在 1~2 秒内先后到达）及群发回执场景，设计**两级防抖聚合队列（800ms Coalescing Window）**：
1. **后端事件载荷升级**：
   - 将 `winrt.rs` 和 `lib.rs` 中发射的 `"sms-received"` 事件载荷统一规范化为结构化对象：
     ```json
     {
       "phone": "106589665200",
       "content": "【中国移动线上营业厅】您的验证码是：636642...",
       "timestamp": "2026-11-09T09:58:58Z",
       "partIndex": 1,
       "partTotal": 2,
       "groupId": "106589665200_12"
     }
     ```
2. **前端全局 `<GlobalSmsNotifier />`（挂载于 `Layout.tsx` 顶层）**：
   - **长短信分片聚合防抖**：当收到 `partTotal > 1` 的分片事件时，不立即弹窗，而是开启 **800ms 滑动聚合定时器**（以 `phone` 为 key），等待后续分片入库并在内存中拼合完整正文后，**仅弹出一次完整内容的横幅 Banner**！
   - **单汉堡栈（Single Active Banner with Counter）**：顶部浮窗同一时刻最多展示 **1 条**最新横幅（若 3 秒内连续收到多条不同短信，在横幅右上角显示 `+2 条新消息` 角标并平滑替换正文），停留 **8 秒**（验证码类短信延长至 **12 秒**）后自动上滑收起，鼠标悬停（`:hover`）时暂停倒计时。
   - **Web Audio API 内置清脆提示音**：由于 Windows 11 原生 Toast 在未签名绿色单文件 `.exe` 下经常被系统静默拦截，前端在 `notify_sound === true` 时，直接使用浏览器原生 `AudioContext` 合成一段零外部音频文件依赖的双音和弦（如 `587.33Hz D5` $\rightarrow$ `880Hz A5`，180ms 清脆叮咚声），100% 穿透 Win11 Toast 限制。

## 三、可直接落地的完整核心代码实现

### 1. 新增 `src/lib/sms-parser.ts`（机构签名识别 + 验证码提取 + WebAudio 提示音）

```typescript
/**
 * SMSClient — 智能短信语义解析器 (机构签名识别 + 验证码提取 + 内置合成提示音)
 */

export interface ParsedSmsMeta {
  /** 提取出的机构名称，如 "中国移动线上营业厅" */
  signature: string | null;
  /** 去除头部签名后的纯净正文预览 */
  cleanBody: string;
  /** 是否为验证码短信 */
  isOtp: boolean;
  /** 提取出的 4~8 位验证码 */
  otpCode: string | null;
  /** 是否属于可信网关/官方服务号（防私人号码伪造签名） */
  isTrustedServiceNumber: boolean;
}

const KNOWN_CARRIER_MAP: Record<string, string> = {
  "10086": "中国移动",
  "1008611": "中国移动话费服务",
  "10010": "中国联通",
  "10000": "中国电信",
  "10001": "中国电信自助服务",
};

const OTP_KEYWORDS = /验证码|校验码|动态码|确认码|随机码|激活码|登录码|verification\s*code|security\s*code|otp/i;

/**
 * 判断号码是否为运营商短号、106 行业网关号或 95/96 金融客服号
 */
export function isServiceNumber(phone: string): boolean {
  const p = phone.trim();
  if (KNOWN_CARRIER_MAP[p]) return true;
  // 106 行业短信网关 / 100xx 运营商 / 95xxx 银行客服 / 123xx 政务服务
  return /^(106\d{5,15}|100\d{2,5}|9[56]\d{3,6}|12[13]\d{2,5})$/.test(p);
}

/**
 * 从单条短信或会话历史中解析机构签名与验证码
 */
export function parseSmsContent(phone: string, content: string): ParsedSmsMeta {
  const raw = (content || "").trim();
  const isTrusted = isServiceNumber(phone);

  // 1. 提取头部或尾部的 【机构签名】
  let signature: string | null = null;
  let cleanBody = raw;

  const headMatch = raw.match(/^\s*【([^】]{2,18})】\s*/);
  const tailMatch = raw.match(/\s*【([^】]{2,18})】\s*$/);

  if (headMatch) {
    signature = headMatch[1].trim();
    cleanBody = raw.slice(headMatch[0].length).trim();
  } else if (tailMatch) {
    signature = tailMatch[1].trim();
    cleanBody = raw.slice(0, raw.length - tailMatch[0].length).trim();
  } else if (KNOWN_CARRIER_MAP[phone]) {
    signature = KNOWN_CARRIER_MAP[phone];
  }

  // 2. 识别并提取验证码
  const hasOtpKeyword = OTP_KEYWORDS.test(raw);
  let otpCode: string | null = null;

  if (hasOtpKeyword) {
    // 优先匹配关键词紧邻的 4~8 位纯数字（排除年份 2026、金额如 100.00、尾号等）
    const nearMatch = raw.match(
      /(?:验证码|校验码|动态码|确认码|随机码|码|code)[为是：\s:]*([0-9]{4,8})\b/i,
    );
    if (nearMatch) {
      otpCode = nearMatch[1];
    } else {
      // 兜底匹配独立的 4~6 位数字（避开手机尾号、日期、端口号）
      const candidates = [...raw.matchAll(/(?<![0-9.-])([0-9]{4,6})(?![0-9.%年月日时分元GBMB])/g)];
      if (candidates.length > 0) {
        otpCode = candidates[0][1];
      }
    }
  }

  return {
    signature,
    cleanBody: cleanBody || raw,
    isOtp: Boolean(hasOtpKeyword && otpCode),
    otpCode,
    isTrustedServiceNumber: isTrusted,
  };
}

/**
 * 聚合会话内多条消息，提取该号码最准确的机构显示名
 */
export function resolveConversationDisplayName(
  phone: string,
  messages: { content: string; direction: "in" | "out" }[],
): { primaryTitle: string; secondaryPhone: string | null; isOfficial: boolean } {
  if (KNOWN_CARRIER_MAP[phone]) {
    return {
      primaryTitle: KNOWN_CARRIER_MAP[phone],
      secondaryPhone: phone,
      isOfficial: true,
    };
  }

  // 从最新到最旧扫描收到的短信中的【签名】
  for (let i = messages.length - 1; i >= 0; i--) {
    const m = messages[i];
    if (m.direction !== "in") continue;
    const meta = parseSmsContent(phone, m.content);
    if (meta.signature && meta.isTrustedServiceNumber) {
      return {
        primaryTitle: meta.signature,
        secondaryPhone: phone,
        isOfficial: true,
      };
    }
  }

  return {
    primaryTitle: phone,
    secondaryPhone: null,
    isOfficial: false,
  };
}

/**
 * 使用 Web Audio API 合成清脆的双音通知声（零外部音频资源依赖，100% 规避 Win11 Toast 静音限制）
 */
export function playNotificationChime() {
  try {
    const AudioCtx = window.AudioContext || (window as unknown as { webkitAudioContext: typeof AudioContext }).webkitAudioContext;
    if (!AudioCtx) return;
    const ctx = new AudioCtx();
    const now = ctx.currentTime;

    const notes = [587.33, 880.0]; // D5 -> A5 清脆和弦
    notes.forEach((freq, idx) => {
      const osc = ctx.createOscillator();
      const gain = ctx.createGain();
      osc.type = "sine";
      osc.frequency.setValueAtTime(freq, now + idx * 0.11);

      gain.gain.setValueAtTime(0.001, now + idx * 0.11);
      gain.gain.exponentialRampToValueAtTime(0.18, now + idx * 0.11 + 0.02);
      gain.gain.exponentialRampToValueAtTime(0.0001, now + idx * 0.11 + 0.28);

      osc.connect(gain);
      gain.connect(ctx.destination);
      osc.start(now + idx * 0.11);
      osc.stop(now + idx * 0.11 + 0.3);
    });
  } catch {
    // 忽略音频设备不可用异常
  }
}
```

### 2. 修复 `src-tauri/src/lib.rs` 与 `src-tauri/src/sms/mod.rs`（消除每 15 秒虚假事件发射）

在 `src-tauri/src/sms/mod.rs` 中，记录本次同步**真正新插入数据库的短信列表 `newly_inserted`**，或者新增 `sync_inbox_and_get_new(db: &DbState)`。最简洁的改法是在 `sync_inbox_non_blocking` 中当 `newly_inserted` 非空时直接由其内部或返回给 `lib.rs` 发射带完整载荷的 `"sms-received"`：


### 4. 全局顶部浮窗组件 `src/components/layout/GlobalSmsBanner.tsx`（挂载于 `Layout.tsx`）

在 `Layout.tsx` 中挂载全局横幅，使用 800ms 滑动防抖窗口自动合并长短信分片，支持**一键复制验证码**与**点击直接跳转定位会话**：

```tsx
import { useEffect, useState, useRef, useCallback } from "react";
import { listen } from "@tauri-apps/api/event";
import { useNavigate, useLocation } from "react-router-dom";
import { Bell, Copy, Check, ArrowRight, X } from "lucide-react";
import { getSetting } from "@/lib/tauri-bridge";
import { parseSmsContent, playNotificationChime } from "@/lib/sms-parser";

interface SmsEventPayload {
  phone?: string;
  content?: string;
}

interface BannerState {
  phone: string;
  signature: string | null;
  cleanBody: string;
  otpCode: string | null;
  count: number;
}

export function GlobalSmsBanner() {
  const [banner, setBanner] = useState<BannerState | null>(null);
  const [copied, setCopied] = useState(false);
  const navigate = useNavigate();
  const location = useLocation();
  const dismissTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);
  const coalesceTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);
  const pendingRef = useRef<{ phone: string; parts: string[] } | null>(null);

  const scheduleDismiss = useCallback((isOtp: boolean) => {
    if (dismissTimerRef.current) clearTimeout(dismissTimerRef.current);
    dismissTimerRef.current = setTimeout(
      () => setBanner(null),
      isOtp ? 12000 : 8000,
    );
  }, []);

  useEffect(() => {
    const unlisten = listen<SmsEventPayload | null>("sms-received", async (event) => {
      const payload = event.payload;
      if (!payload || !payload.phone || !payload.content) return;

      // 800ms 分片聚合防抖：避免长短信 2~3 个分片触发多次闪烁
      if (
        pendingRef.current &&
        pendingRef.current.phone === payload.phone
      ) {
        pendingRef.current.parts.push(payload.content);
      } else {
        pendingRef.current = {
          phone: payload.phone,
          parts: [payload.content],
        };
      }

      if (coalesceTimerRef.current) clearTimeout(coalesceTimerRef.current);
      coalesceTimerRef.current = setTimeout(async () => {
        const item = pendingRef.current;
        pendingRef.current = null;
        if (!item) return;

        const fullContent = item.parts.join("");
        const meta = parseSmsContent(item.phone, fullContent);

        // 检查声音设置并播放合成提示音
        const soundPref = await getSetting("notify_sound").catch(() => "true");
        if (soundPref !== "false") {
          playNotificationChime();
        }

        setCopied(false);
        setBanner((prev) => ({
          phone: item.phone,
          signature: meta.signature,
          cleanBody: meta.cleanBody,
          otpCode: meta.otpCode,
          count: prev ? prev.count + 1 : 1,
        }));
        scheduleDismiss(meta.isOtp);

        // 广播自定义 DOM 事件供 Inbox 页面执行智能切焦与呼吸高亮
        window.dispatchEvent(
          new CustomEvent("smsclient:new-message", {
            detail: {
              phone: item.phone,
              content: fullContent,
              isOtp: meta.isOtp,
              otpCode: meta.otpCode,
            },
          }),
        );
      }, 650);
    });

    return () => {
      unlisten.then((fn) => fn());
    };
  }, [scheduleDismiss]);

  if (!banner) return null;

  const handleCopyOtp = async (e: React.MouseEvent) => {
    e.stopPropagation();
    if (!banner.otpCode) return;
    await navigator.clipboard.writeText(banner.otpCode);
    setCopied(true);
    setTimeout(() => setBanner(null), 1500);
  };

  const handleJumpToConversation = () => {
    const targetPhone = banner.phone;
    setBanner(null);
    if (location.pathname !== "/inbox") {
      navigate(`/inbox?phone=${encodeURIComponent(targetPhone)}`);
    } else {
      window.dispatchEvent(
        new CustomEvent("smsclient:select-phone", {
          detail: { phone: targetPhone },
        }),
      );
    }
  };

  return (
    <div
      onMouseEnter={() => {
        if (dismissTimerRef.current) clearTimeout(dismissTimerRef.current);
      }}
      onMouseLeave={() => scheduleDismiss(Boolean(banner.otpCode))}
      onClick={handleJumpToConversation}
      className="fixed top-3 left-1/2 -translate-x-1/2 z-50 w-[92%] max-w-xl cursor-pointer rounded-xl border-2 border-brand-primary bg-card/95 backdrop-blur-md px-4 py-3 shadow-xl transition-all animate-in fade-in slide-in-from-top-4"
    >
      <div className="flex items-center justify-between gap-3">
        <div className="flex items-center gap-2.5 min-w-0 flex-1">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-brand-primary text-white animate-pulse">
            <Bell size={15} />
          </span>
          <div className="min-w-0 flex-1">
            <div className="flex items-center gap-2">
              <span className="text-xs font-bold text-brand-primary">
                新短信到达
              </span>
              {banner.signature && (
                <span className="rounded bg-brand-primary/10 px-1.5 py-0.5 text-xs font-semibold text-brand-primary">
                  【{banner.signature}】
                </span>
              )}
              <span className="font-mono text-xs text-muted-foreground truncate">
                {banner.phone}
              </span>
              {banner.count > 1 && (
                <span className="rounded-full bg-brand-accent px-1.5 py-0.2 text-[10px] font-bold text-white">
                  +{banner.count}
                </span>
              )}
            </div>
            <p className="mt-0.5 text-sm font-medium text-foreground truncate">
              {banner.cleanBody}
            </p>
          </div>
        </div>

        <div className="flex items-center gap-2 shrink-0">
          {banner.otpCode && (
            <button
              onClick={handleCopyOtp}
              className="flex items-center gap-1.5 rounded-md bg-brand-primary px-3 py-1.5 text-xs font-semibold text-white hover:opacity-90 transition-opacity shadow-sm"
            >
              {copied ? <Check size={13} /> : <Copy size={13} />}
              {copied ? "已复制" : `复制验证码 ${banner.otpCode}`}
            </button>
          )}
          <button
            onClick={(e) => {
              e.stopPropagation();
              handleJumpToConversation();
            }}
            className="flex items-center gap-1 rounded-md border border-border bg-background px-2.5 py-1.5 text-xs font-medium text-foreground hover:bg-accent/10"
          >
            查看 <ArrowRight size={12} />
          </button>
          <button
            onClick={(e) => {
              e.stopPropagation();
              setBanner(null);
            }}
            className="p-1 text-muted-foreground hover:text-foreground"
            aria-label="关闭通知"
          >
            <X size={14} />
          </button>
        </div>
      </div>
    </div>
  );
}
```
